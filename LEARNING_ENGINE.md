# Learning Engine

## Purpose
Improve system-level knowledge and workflows over time. This does not mean the model weights are continuously retrained. Initial learning uses research, curated knowledge, memory, tool discovery and evaluated process improvements.

## Learning cycle
1. Identify a gap, repeated failure, outdated fact or requested topic.
2. Define the research question, scope, freshness and budget.
3. Collect approved sources.
4. Extract claims, context, dates and metadata.
5. Compare evidence, detect duplicates and contradictions.
6. Validate authority, relevance, recency and corroboration.
7. Ask the user when meaning is subjective, personal or ambiguous.
8. Propose a knowledge update or skill.
9. Review and request approval for sensitive knowledge, permissions or code changes.
10. Store versioned results and evaluate usefulness.

## Sources
Potential sources include user explanations, approved documentation, reputable websites, APIs, repositories and task outcomes. Follow source terms and user permissions.

## User-guided learning
Do not pretend external research can resolve every personal or philosophical concept. Ask a focused question when the user's own meaning or preference is needed. Keep personal definitions separate from universal facts.

## Budgets
Every job needs limits for time, source count, model calls and estimated spend. Deduplicate before summarizing. Stop when evidence is adequate or budget is reached. Report failures and skipped work.

## Output
Record the question, scope, sources, retrieval dates, extracted claims, uncertainty, conflicts, proposed updates, validation status and estimated usage.

## Do not
Treat snippets as verified facts, store every chat permanently, silently promote weak claims, execute downloaded code or grant unrestricted account access.
